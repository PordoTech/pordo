# 音乐歌单与漫画目录排序记忆方案

状态：桌面端已实现；歌单与漫画目录排序偏好均在本机保存。

## 1. 范围与现状

本方案以当前桌面端 Rust / egui 界面为基准。音乐页目前包含「收藏 / 搜索」标签、最近聆听封面卡片和收藏歌曲列表；播放使用独立的音乐队列，支持本地歌曲与在线歌曲。

本次新增：创建和管理歌单、把收藏歌曲加入歌单、播放整个歌单。同时让每本收藏漫画分别保存详情目录的排序选择，默认仍为正序。

首版歌单在本机持久化；跨设备同步、外部歌单导入、分享、自定义封面和 Android 界面适配列为后续范围，避免与现有在线收藏同步产生隐含承诺。

## 2. 视觉语言

直接沿用 `src/app/design.rs` 的组件和颜色，不新增独立主题。

| 元素 | 方案 |
| --- | --- |
| 背景 / 表面 | `BACKGROUND` #111315 / `SURFACE` #191D20 |
| 主色 / 当前项 | `ACCENT` #A9E0CD / `SELECTED` #253732 |
| 正文 / 辅助文字 | `TEXT` #EEF0EC / `MUTED` #929A9D |
| 按钮 / 输入 | 36 高，复用主按钮、描边按钮、图标按钮和输入框 |
| 卡片 | 复用音乐封面卡片的 10 圆角、8 内边距和 12 列间距 |
| 歌曲列表 | 延续 62 高歌曲行、42 × 42 封面、标题与艺术家两行排版 |
| 图标与反馈 | 沿用现有图标库、悬停底色、提示和焦点样式；主色用于主要动作和选中状态 |

歌单封面优先使用前四首可用歌曲的封面拼图；一首时使用单图，二至三首时用占位格补齐，空歌单用现有音乐图标和深绿色底。缺失封面使用相同占位，不生成装饰性插画。

## 3. 页面结构

音乐页新增「歌单」标签，顺序为「收藏 / 歌单 / 搜索」，沿用现有标签样式。保留左侧主导航、底部播放条和右侧队列。

歌单列表：

```text
音乐
收藏    歌单    搜索

我的歌单  3                         [+ 新建歌单]

[封面拼图]       [封面拼图]       [音乐占位]
通勤             夜间             新歌待听
24 首歌曲        16 首歌曲        0 首歌曲
```

- 卡片采用现有音乐卡片的自适应列数；标题一行截断，悬停可查看完整名称。
- 单击卡片进入详情；封面悬停显示独立播放按钮，点击直接播放该歌单，不触发卡片跳转。
- 卡片菜单提供「播放 / 重命名 / 删除歌单」。空歌单禁用播放。
- 没有歌单时显示音乐图标、「创建歌单，整理喜欢的歌曲」和「新建歌单」按钮。

歌单详情：

```text
← 我的歌单

[歌单封面]   通勤
             24 首歌曲
             [▶ 播放全部]  [+ 添加歌曲]  [⋯]

#    标题 / 艺术家                  专辑    时长    ⋯
1    [封面] 歌曲标题                …       03:42   ⋯
            艺术家
```

- 返回时恢复歌单列表滚动位置。
- 复用收藏歌曲行，右侧保留收藏按钮，增加更多操作入口。
- 歌曲行菜单包括「播放 / 添加到其他歌单 / 从此歌单移除」。
- 详情支持长按拖动排序，沿用队列的拖动手势与插入线；菜单提供上移、下移作为替代操作。
- 狭窄内容区域先隐藏专辑列，再折叠次要动作到菜单；标题、返回、播放和更多入口始终可用。以打开右侧队列后的实际内容宽度判断。

## 4. 创建与添加歌曲

新建歌单使用简洁对话框，只填写名称；默认占位「例如：通勤、夜间」。名称去除首尾空白，限制为 1–40 个字符。空名称禁用提交，同名时就地提示。Enter 提交，Esc 取消。

两个添加入口共用歌曲选择与歌单选择组件：

1. 收藏歌曲行增加「更多 → 添加到歌单」。弹出歌单选择框，选择目标后立即添加并反馈「已添加到『通勤』」；已包含该歌曲的歌单显示「已添加」并禁用。提供「新建歌单」入口，创建后自动完成本次添加。
2. 歌单详情点击「添加歌曲」，打开收藏歌曲选择框。支持按标题、艺术家、专辑搜索，勾选多首后点击「添加 N 首」。已在歌单中的歌曲显示已添加，不重复计入数量。确认后按选择框中的显示顺序追加。

详情空状态为「歌单里还没有歌曲」与「从收藏添加」。若没有收藏，提示「先收藏喜欢的歌曲，再加入歌单」，提供返回收藏页的入口。

歌单与收藏是独立关系：同一首歌曲可在多个歌单中；取消收藏仍保留歌单成员；从歌单移除歌曲保留收藏与文件。添加与移除操作提供简短反馈，移除支持撤销。删除歌单需显示名称确认，文案明确「歌曲、收藏和文件会保留」。

## 5. 播放语义

- 「播放全部」按歌单保存的顺序生成音乐队列，从第一首开始，打开现有右侧队列；保留视频队列。
- 在歌单详情双击歌曲或选择「播放」，生成完整歌单队列，从该首开始，让后续播放自然沿歌单继续。
- 保持详情页可见，底部播放条与当前歌曲行即时更新；用户通过现有入口进入歌词页。
- 顺序、随机、循环等播放方式复用现有播放器设置，不为歌单创建另一套开关。
- 队列是开始播放时的快照。调整歌单顺序、增删歌曲、删除歌单不会中断或改写当前队列；再次播放歌单时使用最新内容。
- 在线歌曲保存来源信息，播放时重新获取可用地址，不持久化临时播放 URL。本地歌曲使用现有文件播放流程。
- 本地文件不存在或在线歌曲不可用时，在队列标明原因并按现有跳过策略继续；全部不可用时停止，明确提示，防止循环重试。空歌单不创建队列。

## 6. 数据与实现边界

新增独立的歌单存储与 UI 状态模块，避免把歌单当作带特殊名称的收藏或队列。歌单结构包含稳定 UUID、名称、创建和修改时间、有序歌曲成员。使用带版本的独立 JSON 文件和原子写入；写入失败展示错误，不提示保存成功。

成员保存稳定身份和播放所需的最小元数据：在线歌曲优先使用现有来源与 `OnlineSong::key()`，本地歌曲使用文件路径。在线歌曲下载为本地文件后仍按来源身份去重，不因路径变化变成两首；没有来源关联的普通本地文件仍作为独立歌曲处理。

成员元数据需要在取消收藏、删除历史后仍能播放和展示，不能仅引用当前收藏筛选结果。封面继续使用已有缓存，不写入歌单文件。

实现时提取可复用的歌曲行与播放转换逻辑：收藏页沿用现有行为，歌单页传入歌单上下文和起播位置。歌单存储直接提供创建、重命名、删除、追加、移除和重排操作；UI 只提交操作和展示结果。

现有 `play_records` 已具备替换音乐队列的基础流程；需扩展为指定起播位置。不得直接复用单曲 `play_record` 的追加语义作为歌单内起播行为。

## 7. 收藏漫画详情目录排序记忆

按最新要求：**不改默认正序，按每本收藏漫画保存目录排序设置。**

- 保留详情现有正序 / 倒序图标按钮和提示文字，不增加新的设置界面。
- 新收藏和没有排序记录的旧收藏默认正序；用户切换后立即保存到该收藏条目的本地偏好。
- 每次进入详情先按漫画的来源与书籍 ID 恢复该书设置，不能沿用上一部漫画的内存排序状态。
- 例如 A 选择倒序，B 仍为正序；返回 A 或重启应用后再打开 A，仍为倒序。
- 未收藏漫画进入详情时默认正序，可临时切换；收藏时保存当前选择。取消收藏后不承诺保留此项偏好。
- 只改变详情目录的展示顺序。沿用原始章节索引、分组与筛选，阅读页上一话 / 下一话、继续阅读、已读和更新判断仍按原有章节身份与逻辑工作。
- 首版作为本地偏好保存；现有收藏同步导入不得覆盖本地排序选择。跨设备同步该项偏好可后续单独扩展。

目前 `comic::State` 中的 `reverse` 是初始化为 false 的共享运行状态。实现应将保存值挂在漫画收藏条目上，打开详情时装载，切换时更新并触发持久化；旧数据缺字段时使用 false。

## 8. 验收重点

- 从收藏添加本地和在线歌曲、批量添加、去重、重命名、删除、重排，以及重启后的恢复。
- 取消收藏或删除播放历史后，歌单内容与可播放信息仍保留。
- 从歌单中间起播时队列完整、当前位置正确；视频队列保持；编辑歌单不干扰正在播放的队列。
- 空歌单、全不可用、部分不可用、封面缺失、存储失败都有明确反馈。
- 中英文文案、窄窗口、展开队列、长歌单名称、键盘焦点和嵌套按钮点击均验证。
- 漫画 A / B 独立排序、旧收藏默认正序、重启恢复、未收藏详情不串用排序，以及倒序目录下点击对应章节与阅读前后导航均验证。

实施顺序：歌单存储与身份处理 → 页面及添加流程 → 播放衔接 → 漫画排序持久化 → 对应行为验证和界面检查。
